Resolved by direct testing: the game silently strips every XML comment from the .binds file on load/rewrite (a well-behaved normalize, not a lossy one — actual binding values survive intact). Group-membership metadata cannot live in .binds comments and must live in BindForge's own data store instead.
Control Types (named "Type Mode" in earlier design docs) — primary intended grouping is axis vs. button, matching the three-kind binding schema (button-type / axis-type / standalone-setting-type); a finer breakdown by input type (keyboard, joystick axis, joystick button, POV/hat) was also considered. Confirmed out of v1 scope, parked — see Bind Editor § Control Types.
Controller Mode — back-burner concept. Each numbered field would be a searchable dropdown to assign a bind slot to that physical button/axis. Licensing and per-device diagram sourcing both unresolved — see BindForge_Spec.md roadmap.
Input Mode — press or select a physical control and see every binding, across all sections, that uses it. Real capture will use the same device-polling layer already built for the Alias Designer. This mockup simulates detection since there's no live hardware here. Clicking a row is meant to open the same capture dialog used everywhere else in BindForge, in place — not built in this mockup, since the real version is a floating dialog matching the base game's own rebind popup rather than something this inline mockup approximates well.
