  points.** The percentages are a judgement of effort, not a measurement.

  finished:** Alias Designer and File Manager. Game Mode is about half done, and Preset Editor, Anomalies and Settings are not on screen yet.

  [Split the panel first](#do-this-first-g0-split-the-bind-editor-panel), then keep the capture dialog with one person.

## How we avoid merge conflicts

### Who holds which file

| File or area | Used by | Rule |
|---|---|---|
| `BindingProfilePanel` | S12, G0, then a little by AN3, ST | Alan's until G0 is merged. Nobody else opens it before then. After that, only a new tab line each |
| `GameModePanel`, `BindingsGroupTableFactory` | E3, E6c, GM1; AN2, AN5 lightly | Alan's. Krondor says when he is in it, and keeps it to the lines the task names |
| `AssignKeyboardBindingDialog`, `ControllerInputsPanel`, `ControllerCapture` | E2-E5 | Alan's alone. Anomalies uses `openCapture` |
| `BindingsWriter`, `KeyBindingsParser` | S12, E6b, and any V1.1 fix | Alan's for the features; Krondor warns before merging a V1.1 fix that touches them |
| `bindforge.rules`, `BindingsMonitor` | AN2, E5's `SlotInputConflicts`, and V1.1 fixes | Krondor's. AN2 and E5 talk first if the service would absorb `SlotInputConflicts` |
| `BindingsTabPanel` | P4, FIN | Krondor's |
| `AiAccess`, `BindingSlotCellRenderer` | AN4, GM1 | Whichever is in first merges first; the other merges `V1.2` before starting |
| Nine `gui*.properties` bundles | Almost every task | See below |
| `db-migration/` | AN4; anything else on V1.2 | See below |

### Working rules

1. **Each lane has a branch off `V1.2`, and merges each task when it
   passes,** not at the end. Merge `V1.2` in at the start of every session. Long-lived branches are what made the 2026-10-31 merge expensive. (Alan's can simply stay `V1.2-BindForge`; [D2](#decisions-to-make-together).)
2. **Never add strings at the end of a
   bundle.** Today's new keys land there, in all nine, so two branches always collide. G0 seeds a comment block per lane; each lane adds under its own, leaving at least one unchanged line between the blocks.
3. **Migrations take the next free number when merged, not when
   written.** An unshipped one that clashes is renumbered by whoever merges second. AN4 is the only migration this plan expects, but `V1.2`'s other work takes `12XXX` numbers too.
4. **No reformatting, import sorting or tidying in a file the other lane
   uses.** It turns a three-line change into a whole-file conflict. G0 is the one allowed move, and it merges alone.
5. **Each brief has one
   writer,** its lane's. The status rows in [README.md](README.md) are single long, adjacent lines, so any two edits conflict: update them only while merging into `V1.2`. `bindforge/PACKAGE.md` is the same: change your own row only.
6. **Say so before crossing a
   lane.** One line in chat ("I need `AiAccess` today") costs less than any merge. Anything found out of lane goes in the owner's brief, per the existing routine.
7. **Krondor warns before merging `V1.1-Release`
   up** when the fix touches `bindforge.rules` or `bindforge.io`, so Alan merges right after.
8. **The session routine is the same for
   both,** with one change: `/next-slice` is worded for Alan as the approver and the committer. In Lane B, read that as Krondor.
