## Локальна LLM — налаштування на Windows (LM Studio)

Запуск локальної LLM зберігає всі дані приватними та офлайн. Плата за підписку відсутня. Застосовуються витрати на обладнання та електроенергію.

Для роботи потрібні [LM Studio](https://lmstudio.ai) та здатний GPU.

---

### Мінімальні вимоги до обладнання

Щоб запустити Elite Dangerous та LLM на **одній машині**, потрібен мінімум **NVIDIA RTX 3060 з 12 GB VRAM**.

> **Порада:** Elite Intel можна спрямувати на екземпляр LM Studio, що працює на **окремому ПК** у вашій мережі. Якщо доступна друга машина зі здатним GPU, ігровий ПК не несе жодного навантаження від інференсу в цій конфігурації.

### Крок 1 — Встановлення LM Studio

Відкрийте **PowerShell** та виконайте:

```powershell
irm https://lmstudio.ai/install.ps1 | iex
```

Це встановлює CLI `lms` та **llmster** — фоновий сервер LM Studio. Настільний додаток LM Studio при цьому **не** встановлюється. Після встановлення відкрийте **нове** вікно PowerShell, щоб зміни набули чинності.

Перевірте, що все працює:

```powershell
lms --help
```

> **Примітка:** Якщо настільний додаток LM Studio вже встановлено, CLI `lms` може бути вже доступний. Виконайте `lms --help` перед запуском скрипта встановлення.

---

### Крок 2 — Завантаження моделі

Запустіть фоновий сервер LM Studio, а потім завантажте модель:

```powershell
lms daemon up
lms get google/gemma-4-e4b
```

Якщо ім'я не збігається точно, `lms get` покаже знайдені варіанти — оберіть потрібний
стрілками та клавішею Enter.

[LM Studio має відомий баг](https://github.com/lmstudio-ai/lmstudio-bug-tracker/issues/917). У деяких випадках завантаження завершується помилкою:
```Error: No staff picks found with the specified search criteria.```

У такому разі завантажте GGUF вручну зі сторінки моделі на HuggingFace та імпортуйте його:

```powershell
lms import C:\path\to\the-model.gguf
```

Щоб переглянути завантажені моделі:

```powershell
lms ls
```

---

### Крок 3 — Запуск сервера

Завантажте модель та запустіть сервер інференсу:

```powershell
lms daemon up
lms load google/gemma-4-e4b --context-length 8192 --gpu max
lms server start
```

`lms daemon up` нічого не робить, якщо фоновий сервер уже запущено, тому його можна безпечно виконувати щоразу.

**ПРИМІТКА**: Прапорець `--context-length 8192` є обов'язковим. Без нього вікно контексту може бути надто малим, що спричиняє обрізання запитів, помилки та галюцинації.

Перевірте, що сервер запущений, відкривши браузер або інше вікно PowerShell і перейшовши до:

```
http://localhost:1234/v1/models
```

Ви отримаєте JSON-список завантажених моделей. Рядок ідентифікатора моделі у цій відповіді — це те, що ви введете у поле **Модель** в Elite Intel.

Щоб зупинити сервер:

```powershell
lms server stop
```

> ⚠️ **Важливо:** Сервер LM Studio **не** переживає перезавантажень. Виконуйте три команди з кроку 3 після кожного перезапуску або скористайтесь одним із варіантів автозапуску нижче.

---

### Крок 4 — (Необов'язково) Автозапуск при завантаженні

Доступні два варіанти для підтримки роботи сервера після перезавантажень. Якщо ви виконали крок 1, використовуйте **варіант A**. Варіант B лише для тих, у кого також встановлено настільний додаток LM Studio.

#### Варіант A — Планувальник завдань (настільний додаток не потрібен)

Спершу збережіть цей скрипт як `start-lmstudio.ps1` у постійному місці (наприклад, `C:\Scripts\`):

```powershell
$lms = "$env:USERPROFILE\.lmstudio\bin\lms.exe"
& $lms daemon up
& $lms load google/gemma-4-e4b --yes --context-length 8192 --gpu max
& $lms server start
```

Він запускає фоновий сервер, завантажує модель із налаштуваннями, потрібними Elite Intel, і запускає сервер інференсу — ті самі три команди, що й у кроці 3.

Потім створіть завдання:

1. Натисніть **Win + R**, введіть `taskschd.msc`, натисніть Enter.
2. Натисніть **Create Task** на правій панелі.
3. Вкладка **General**: назвіть `LM Studio Server`. Галочку **«Run with highest privileges»** не ставте: LM Studio не потребує прав адміністратора.
4. Вкладка **Triggers**: натисніть New → **«At log on»** → OK.
5. Вкладка **Actions**: натисніть New → **«Start a program»**.
   - Program/script: `powershell.exe`
   - Add arguments: `-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "C:\Scripts\start-lmstudio.ps1"`

`-WindowStyle Hidden` не дає вікну консолі залишатися відкритим після кожного входу. Під час запуску скрипта вікно може ненадовго блимнути.

#### Варіант B — Настільний додаток

Цей варіант доступний, лише якщо встановлено настільний додаток LM Studio. Крок 1 його не встановлює.

1. Відкрийте LM Studio та натисніть **Ctrl + ,** для відкриття налаштувань.
2. Поставте галочку **«Run LLM server on login»**.
3. Закриття додатка згортає його до системного трею та залишає сервер запущеним. При наступному вході він відновлюється автоматично.

> ⚠️ **Довжина контексту:** У цьому варіанті LM Studio завантажує модель лише тоді, коли надходить перший запит, і використовує **типові** налаштування моделі замість `--context-length 8192` з кроку 3. Відкрийте типові налаштування моделі в настільному додатку та встановіть **Context Length** на **8192**. Інакше вікно контексту може виявитися надто малим.

---

### Крок 5 — Налаштування Elite Intel

Відкрийте в Elite Intel **Сервіси → Сервіси ШІ**. У розділі **Мовна модель (LLM)** виберіть **LMStudio**:

- **Адреса**: `http://localhost:1234/v1/chat/completions` (типове значення). Якщо LM Studio на іншій машині, замініть `localhost` на IP цієї машини.
- **Модель**: вставте рядок ідентифікатора моделі з `http://localhost:1234/v1/models`. Одна модель обслуговує і команди, і запити.

Для локального LLM ключ API не потрібен.

Натисніть **Зберегти**. Elite Intel сам перезапустить мовну модель.
