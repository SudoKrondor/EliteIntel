# Частина 1. Ubuntu Server як хост для локального ШІ / LM Studio

**Посібник із чистого базового встановлення**  
**Рекомендована база:** Ubuntu Server 24.04 LTS (amd64)  
**Дата документа:** 12 вересня 2026

## 1. Призначення

Цей посібник готує чисту машину з Ubuntu Server для роботи локального ШІ без графічного інтерфейсу, наприклад LM Studio / llmster. Він навмисно закінчується до встановлення самого LM Studio. Мета — невеликий і зрозумілий сервер із робочими мережею, SSH, оновленнями, брандмауером і, за потреби, перевіреним драйвером NVIDIA.

Це не посібник із відновлення чи діагностики обладнання. Передбачається, що машина стабільно працює на штатних налаштуваннях CPU/RAM, а важливі дані вже збережено.

## 2. Яка версія Ubuntu?

Для консервативного, довговічного ШІ-сервера цей посібник використовує **Ubuntu Server 24.04 LTS (Noble Numbat)**. Canonical забезпечує стандартне обслуговування безпеки Ubuntu 24.04 LTS до травня 2029 року. Ubuntu 26.04 LTS також доступна і є новішою LTS, але 24.04 і надалі повністю підтримується та залишається зрілою основою для систем, де стабільність важливіша за найновіше ядро й користувацьке оточення.

Для зовсім нового встановлення, коли новому обладнанню потрібен найсвіжіший стек ядра й драйверів, Ubuntu 26.04 LTS — теж розумний вибір. Команди в цьому посібнику навмисно стандартні й мають лишитися майже такими самими.

Офіційні посилання:
- https://ubuntu.com/about/release-cycle
- https://documentation.ubuntu.com/release-notes/24.04/
- https://ubuntu.com/server/docs/tutorial/basic-installation/

## 3. Перед встановленням

Підготуйте:

- 64-бітну машину Intel/AMD (amd64).
- USB-накопичувач з ISO-образом Ubuntu Server.
- За можливості дротовий Ethernet.
- Ім'я хоста, ім'я користувача й надійний пароль.
- Рішення, який диск Ubuntu може стерти.
- Для інференсу на GPU — підтримувану відеокарту NVIDIA, правильно встановлену й підключену до живлення.

Якщо раніше CPU або RAM працювали з розгоном, перед введенням машини в роботу як сервера поверніть стабільні штатні налаштування. Середовища виконання ШІ та компіляція модулів ядра можуть виявити нестабільність, яка не проявляється за легшого навантаження.

## 4. Встановлення Ubuntu Server

Завантажте інсталятор Ubuntu Server і дотримуйтеся звичайного порядку. Для простого виділеного сервера:

1. Виберіть мову й розкладку клавіатури.
2. Дозвольте інсталятору спочатку налаштувати дротову мережу через DHCP.
3. Використайте призначений системний диск. **Розмітка диска може знищити наявні дані**, тож уважно перевірте вибраний диск.
4. Створіть користувача-адміністратора та ім'я хоста.
5. Виберіть **Install OpenSSH server**, коли це буде запропоновано. Якщо не вибрали, його можна встановити після першого завантаження.
6. Пропустіть додаткові серверні snap-пакети, якщо вони вам спеціально не потрібні.
7. Завершіть встановлення й перезавантажтеся.

## 5. Перший вхід і оновлення системи

Увійдіть локально або через SSH, потім оновіть індекс пакетів і встановлені пакети:

```bash
sudo apt update
sudo apt upgrade -y
```

Якщо Ubuntu повідомляє, що потрібне перезавантаження:

```bash
sudo reboot
```

Після повторного підключення перевірте версію системи та ядра:

```bash
lsb_release -a
uname -r
```

## 6. Невеликий набір інструментів адміністрування

На ШІ-сервері без GUI корисні такі пакети:

```bash
sudo apt install -y \
  openssh-server \
  curl \
  ca-certificates \
  jq \
  htop \
  nvtop \
  ufw
```

`curl` використовується інсталятором LM Studio та для перевірки API, `jq` робить вивід JSON читабельним, `htop` стежить за CPU/RAM, `nvtop` — за GPU, а `ufw` дає простий брандмауер хоста.

Переконайтеся, що SSH увімкнено:

```bash
systemctl status ssh --no-pager
```

## 7. Доступ через SSH

Дізнайтеся поточну адресу сервера:

```bash
ip -br address
```

З іншої машини в локальній мережі:

```bash
ssh YOUR_USER@SERVER_IP
```

Для регулярної роботи автентифікація SSH за відкритим ключем зручніша, ніж щоразу вводити пароль. На клієнтській машині:

```bash
ssh-keygen -t ed25519
ssh-copy-id YOUR_USER@SERVER_IP
```

Перевірте новий сеанс SSH, перш ніж змінювати налаштування парольної автентифікації. Не заблокуйте собі доступ до віддаленого сервера.

Офіційна довідка з OpenSSH:
https://ubuntu.com/server/docs/how-to/security/openssh-server/

## 8. Базовий брандмауер

Перед увімкненням UFW дозвольте SSH:

```bash
sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status verbose
```

Для виділеного домашнього ШІ-сервера в локальній мережі краще відкривати порти застосунків лише довіреним клієнтам або довіреній локальній мережі, а не всім мережевим інтерфейсам без розбору.

Порт API LM Studio за замовчуванням — 1234. **Поки що не відкривайте його.** Додайте потрібне правило, коли LM Studio буде встановлено і стане зрозуміло, яким клієнтам потрібен до нього доступ.

Офіційна довідка з брандмауера:
https://ubuntu.com/server/docs/how-to/security/firewalls/

## 9. Драйвер NVIDIA

Пропустіть цей розділ, якщо сервер використовуватиме інференс на CPU або прискорювач не від NVIDIA.

Спочатку оновіть систему й за потреби перезавантажтеся. Потім дозвольте Ubuntu визначити відповідні обчислювальні драйвери NVIDIA:

```bash
sudo ubuntu-drivers list --gpgpu
```

Для обчислювального/серверного навантаження Ubuntu документує автоматичне встановлення командою:

```bash
sudo ubuntu-drivers install --gpgpu
```

Перезавантажтеся після встановлення:

```bash
sudo reboot
```

Потім перевірте GPU:

```bash
nvidia-smi
```

Успішний вивід `nvidia-smi` показує відеокарту, версію драйвера, температуру, VRAM і таблицю процесів.

### Примітка щодо Secure Boot

Secure Boot вимагає сумісних підписаних модулів ядра. Інструмент `ubuntu-drivers` — бажаний спосіб встановлення, бо він призначений для правильного вибору драйверів із пакетів Ubuntu. Якщо модуль NVIDIA не завантажується, перевірте стан Secure Boot, перш ніж знову й знову перевстановлювати драйвери:

```bash
mokutil --sb-state
```

Не вимикайте Secure Boot просто за звичкою як перший крок. Якщо ваша комбінація прошивки й драйвера має проблеми з підписом або реєстрацією MOK, розв'язуйте їх свідомо й документуйте зміну в BIOS.

Офіційна довідка з NVIDIA в Ubuntu:
https://ubuntu.com/server/docs/how-to/graphics/install-nvidia-drivers/

## 10. Підсумкова перевірка готовності

Виконайте:


На цьому етапі на машині мають бути:

- робоче підключення до локальної мережі;
- робочий доступ через SSH;

- корисні інструменти адміністрування;

Сервер готовий до встановлення LM Studio / llmster.

## 11. Що навмисно не розглядається

Ця база не налаштовує сховище NAS/Samba, Docker, бази даних, вебсервери, RAID, нестандартну розмітку дисків, VPN, Pi-hole/DNS, графічні оточення, CUDA Toolkit чи ПЗ для конкретних застосунків. Для цього потрібні окремі посібники.

Окремий CUDA Toolkit **не потрібен лише для запуску LM Studio на підтримуваній відеокарті NVIDIA**; використовуйте стек середовища виконання й драйверів, який підтримує LM Studio, якщо тільки іншому застосунку спеціально не потрібен набір розробника CUDA.

Періодично встановлюйте звичайні оновлення:

```bash
if [ -f /run/reboot-required ]; then

```

Перед переходом на новий великий випуск Ubuntu прочитайте його примітки до випуску й зробіть резервну копію сервера. Перехід між випусками — це не те саме, що звичайні оновлення пакетів.

# Частина 2. LM Studio як сервер без GUI та керування моделями

**Встановлення, вибір моделі, квантизація, служба API та перемикання моделей**  
**Ціль:** сервер Linux/Ubuntu без GUI  
**Дата документа:** 12 вересня 2026

## 1. Призначення

Цей посібник починається з чистого сервера Ubuntu, на якому вже працюють мережа, SSH і — для прискорення NVIDIA — перевірений драйвер GPU. Він встановлює середовище LM Studio без GUI, пояснює, як вибирати й завантажувати моделі, за бажанням відкриває локальний API та пропонує інтерактивний Bash-скрипт для перемикання моделей.

Серверний компонент LM Studio називається **llmster**. Програма командного рядка для керування ним — **lms**. Графічний робочий стіл не потрібен.

Офіційна документація з роботи без GUI:
https://lmstudio.ai/docs/developer/core/headless

## 2. Три назви, які варто розуміти

- **LM Studio** — продукт і екосистема загалом.
- **llmster** — серверний демон без GUI. Він виконує службу інференсу без графічного інтерфейсу.
- **lms** — CLI для завантаження, вивантаження, перегляду та обслуговування моделей.

На виділеному Linux-сервері для інференсу зв'язка llmster + lms зазвичай найчистіша.

## 3. Встановлення llmster / lms

Встановлюйте від імені звичайного користувача, під яким працюватиме служба, а не від root:

```bash
curl -fsSL https://lmstudio.ai/install.sh | bash
```

Запустіть демон:

```bash
lms daemon up
```

Перевірте CLI:

```bash
lms --version
lms --help
```

Якщо оболонка не знаходить `lms`, відкрийте нову оболонку входу або додайте каталог із виконуваними файлами LM Studio до PATH поточної оболонки:

```bash
export PATH="$HOME/.lmstudio/bin:$PATH"
```

Щоб закріпити це для Bash:

```bash
echo 'export PATH="$HOME/.lmstudio/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

## 4. Пошук і завантаження моделей

`lms get` без зазначення моделі показує рекомендації:

```bash
lms get
```

Завантажте модель за її назвою в каталозі:

```bash
lms get publisher/model-name
```

Конкретну модель навмисно залишено на вибір читача, а не зашито в посібник.

Список завантажених моделей:

```bash
lms ls
```

Показати завантажені варіанти/квантизації, якщо вони є:

```bash
lms ls --variants
```

Вивід у JSON зручний для скриптів:

```bash
lms ls --json | jq
```

LM Studio може завантажувати підтримувані моделі зі свого каталогу та екосистеми Hugging Face. Поточна версія CLI також дає змогу вказати квантизацію під час завантаження, наприклад:

```bash
lms get publisher/model-name@q4_k_m
```

Використовуйте назви квантизацій, які справді пропонуються для цієї моделі; не кожна модель публікується в усіх форматах.

Офіційна документація із завантаження моделей:
https://lmstudio.ai/docs/cli/local-models/get

## 5. Розмір моделі та квантизація — пояснення для початківців

Модель містить мільярди навчених числових значень — **ваг**. Вища точність чисел зберігає ці значення точніше, але займає більше місця на диску та в RAM/VRAM. **Квантизація** стискає модель, подаючи ці значення меншою кількістю біт.

Корисна аналогія — якісний аудіозапис: Q8 зберігає більше деталей, Q6 стискає трохи сильніше, Q4 — ще сильніше. Це все версії тієї самої навченої моделі; Q8 не додає чарівним чином нового навчання чи знань.

Типове тлумачення:

| Квантизація | Витрата пам'яті | Точність | Практична роль |
|---|---|---|---|
| Клас Q4 | Нижча | Добра | Чудова відправна точка; часто достатньо для чату/роботи з інструментами |
| Клас Q5/Q6 | Середня | Вища | Добрий баланс якості та пам'яті |
| Клас Q8 | Вища | Дуже висока | Використовуйте, коли додаткова точність помітно допомагає |

LM Studio сам радить вибирати 4-бітний варіант або вище, якщо машина його потягне.

### Важливе правило

**Не вибирайте Q8 лише тому, що 8 більше за 4.** Вибирайте найменшу квантизацію, яка надійно справляється з вашим реальним завданням. Додаткова точність цінна лише тоді, коли вона покращує відповіді, міркування, роботу з інструментами чи стабільність настільки, щоб виправдати постійно більшу витрату пам'яті.

## 6. Розмір моделі — не те саме, що її інтелект

Квантизація й розмір моделі — різні рішення.

Більша й здібніша модель з помірною квантизацією може перевершити меншу модель у Q8 на складних міркуваннях. І навпаки, маленька модель Q4 може ідеально підходити для швидкого тлумачення команд.

Під час вибору моделі враховуйте:

1. **Завдання:** чат, програмування, виклик інструментів/функцій, зір, аналіз даних, ембедінги тощо.
2. **Архітектуру/кількість параметрів:** більші моделі часто здібніші, але потребують більше пам'яті й можуть працювати повільніше.
3. **Квантизацію:** Q4/Q6/Q8 змінює баланс точності й пам'яті для цієї моделі.
4. **Довжину контексту:** більший контекст може споживати додаткову пам'ять.
5. **Чи вміщується в GPU:** якщо модель і робочий контекст повністю у VRAM, інференс на GPU зазвичай найкращий.
6. **Підтримку інструментів:** якщо застосунку потрібен нативний виклик функцій/інструментів, вибирайте модель, навчену й підтримувану для цього.

Правильний вибір залежить від завдання. Перевіряйте на реальних запитах, а не лише за результатами бенчмарків.

## 7. Оцінка пам'яті перед завантаженням

LM Studio може оцінити витрату ресурсів, не завантажуючи модель:

```bash
lms load publisher/model-name \
  --context-length 8192 \
  --gpu max \
  --estimate-only
```

Це оцінка, а не гарантія. Перевірте реально завантажену модель через `lms ps`, `nvidia-smi` і справжній інференс.

## 8. Завантаження та вивантаження моделей

Завантажте отриману модель у пам'ять:

```bash
lms load publisher/model-name --context-length 8192 --gpu max
```

`--gpu max` просить LM Studio перенести на GPU якомога більше. Без цього параметра LM Studio може вибрати автоматично.

Подивитися, що завантажено:

```bash
lms ps
```

Вивантажити модель інтерактивно або за ключем:

```bash
lms unload publisher/model-name
```

Вивантажити все:

```bash
lms unload --all
```

Офіційна довідка:
https://lmstudio.ai/docs/cli/local-models/load

## 9. Запуск HTTP API

Для доступу лише з самого сервера:

```bash
lms server start --bind 127.0.0.1 --port 1234
```

Перевірте:

```bash
curl -s http://127.0.0.1:1234/v1/models | jq
```

Щоб слухати на всіх інтерфейсах IPv4:

```bash
lms server start --bind 0.0.0.0 --port 1234
```

**Безпека:** прив'язка до `0.0.0.0` відкриває службу для всіх доступних мереж. Документація LM Studio радить автентифікацію, якщо служба доступна не лише з localhost. Щонайменше обмежте порт 1234 через UFW довіреними клієнтами локальної мережі або довіреною підмережею. Ніколи не відкривайте API інференсу без автентифікації безпосередньо в інтернет.

Приклад для одного довіреного клієнта:

```bash
sudo ufw allow from CLIENT_IP to any port 1234 proto tcp
```

Приклад для довіреної приватної підмережі (замініть на свою):

```bash
sudo ufw allow from 192.168.1.0/24 to any port 1234 proto tcp
```

Офіційна довідка щодо сервера:
https://lmstudio.ai/docs/cli/serve/server-start

## 11. Автозапуск LM Studio під час завантаження системи

LM Studio документує запуск llmster як завдання автозапуску systemd. Замініть `YOUR_USER`, ключ моделі, довжину контексту та мережеву прив'язку на свої значення.

Створіть службу:

```bash
sudo nano /etc/systemd/system/lmstudio.service
```

Приклад:

```ini
[Unit]
Description=LM Studio Headless Server
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
RemainAfterExit=yes
User=YOUR_USER
Environment="HOME=/home/YOUR_USER"

ExecStartPre=/home/YOUR_USER/.lmstudio/bin/lms daemon up
ExecStartPre=/home/YOUR_USER/.lmstudio/bin/lms load publisher/model-name --context-length 8192 --gpu max --yes
ExecStart=/home/YOUR_USER/.lmstudio/bin/lms server start --bind 127.0.0.1 --port 1234
ExecStop=/home/YOUR_USER/.lmstudio/bin/lms daemon down

[Install]
WantedBy=multi-user.target
```

Увімкніть і запустіть її:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now lmstudio.service
systemctl status lmstudio.service --no-pager
```

Потім перевірте:

```bash
lms ps
curl -s http://127.0.0.1:1234/v1/models | jq
```

### Якщо швидкий запуск CLI видає `Text file busy`

На деяких системах другий виклик `lms` одразу після `lms daemon up` може конфліктувати із запуском демона. Лише якщо ви справді натрапили на цю помилку, додайте коротку паузу між двома рядками `ExecStartPre`:

```ini
ExecStartPre=/home/YOUR_USER/.lmstudio/bin/lms daemon up
ExecStartPre=/bin/sleep 5
ExecStartPre=/home/YOUR_USER/.lmstudio/bin/lms load ...
```

Не додавайте обхідних рішень наперед, якщо проста служба працює.

Офіційна довідка щодо завдання автозапуску:
https://lmstudio.ai/docs/developer/core/headless_llmster

## 12. Інтерактивний перемикач моделей

Супровідний скрипт `lmstudio-model-switcher.sh` (повний текст наприкінці сторінки) виводить просте нумероване меню **ключів завантажених моделей**. Він:

1. перевіряє, що llmster запущено;
2. читає завантажені моделі з `lms ls --json`;
3. питає, яку модель використати;
4. вивантажує поточні завантажені моделі;
5. завантажує вибрану модель із налаштовуваними параметрами контексту/GPU;
6. залишає або за потреби запускає службу API;
7. показує `lms ps` і перевіряє `/v1/models`.

Встановіть його:

```bash
mkdir -p ~/bin
cp lmstudio-model-switcher.sh ~/bin/
chmod +x ~/bin/lmstudio-model-switcher.sh
```

Запустіть з обережними налаштуваннями за замовчуванням (контекст 8192 токени, GPU max, API на localhost):

```bash
~/bin/lmstudio-model-switcher.sh
```

Перевизначте налаштування для одного запуску:

```bash
LMS_CONTEXT_LENGTH=16384 \
LMS_GPU=max \
LMS_BIND=0.0.0.0 \
LMS_PORT=1234 \
~/bin/lmstudio-model-switcher.sh
```

### Важливо: варіанти / квантизації моделей

LM Studio розрізняє **логічний ключ моделі** та її завантажені варіанти квантизації. Завантаження `publisher/model@q4_k_m` вибирає, яку квантизацію зберігати, а під час завантаження в пам'ять зазвичай використовується логічний ключ моделі, який показує `lms ls`.

Якщо ви зберігаєте кілька квантизацій однієї логічної моделі, перегляньте їх так:

```bash
lms ls --variants
lms ls --json | jq
```

Поведінка вибору варіантів змінювалася між версіями CLI LM Studio, тому перед автоматизацією перемикання квантизацій звіртеся з `lms get --help` / `lms load --help` встановленої версії. Доданий скрипт навмисно перемикає **ключі моделей** — це стабільна й зрозуміла операція для посібника загального призначення.

## 13. Зміна моделі за замовчуванням під час завантаження системи

Інтерактивний перемикач змінює те, що завантажено **зараз**. Якщо служба systemd явно завантажує модель під час старту, після перезавантаження знову завантажиться модель, прописана в `/etc/systemd/system/lmstudio.service`.

Щоб зробити іншу модель постійною моделлю за замовчуванням:

```bash
sudo nano /etc/systemd/system/lmstudio.service
```

Змініть рядок `lms load ...`, потім:

```bash
sudo systemctl daemon-reload
sudo systemctl restart lmstudio.service
```

У складнішій конфігурації можна використовувати JIT-завантаження моделей замість закріплення однієї моделі під час старту. LM Studio підтримує JIT-завантаження та автоматичне вивантаження; це корисно, коли застосунки вибирають моделі динамічно.

## 15. Практичний порядок вибору моделі

Розумний спосіб вибрати модель:

1. Спочатку визначте реальне завдання.
2. Знайдіть моделі з потрібними можливостями (наприклад, робота з інструментами, програмування, зір або міркування).
3. Спочатку завантажте варіант класу Q4, якщо він є.
4. Якщо пам'яті впритул, перед завантаженням використайте `--estimate-only`.
5. Перевірте реальні запити та виклики інструментів.
6. Переходьте на Q5/Q6, лише якщо Q4 помітно втрачає в надійності чи якості.
7. Переходьте на Q8, лише якщо покращення помітне й варте додаткової RAM/VRAM.
8. Якщо навіть Q8 маленької моделі недостатньо, спробуйте **більшу/кращу модель з помірною квантизацією**, а не розраховуйте, що ще більша точність розв'яже проблему.

Так вибір моделі лишається емпіричним, а не числовим: **найкраща модель — це найменша/найшвидша конфігурація, яка надійно задовольняє потреби застосунку.**

## Додаток: `lmstudio-model-switcher.sh`

Збережіть це як `lmstudio-model-switcher.sh`, потім встановіть, як описано в частині 2, § 12.

```bash
#!/usr/bin/env bash
set -euo pipefail

# LM Studio interactive model switcher
# Optional environment overrides:
#   LMS_CONTEXT_LENGTH=16384 LMS_GPU=max LMS_BIND=0.0.0.0 LMS_PORT=1234 ./lmstudio-model-switcher.sh

CONTEXT_LENGTH="${LMS_CONTEXT_LENGTH:-8192}"
GPU="${LMS_GPU:-max}"
BIND="${LMS_BIND:-127.0.0.1}"
PORT="${LMS_PORT:-1234}"

need() {
  command -v "$1" >/dev/null 2>&1 || {
    echo "Error: '$1' is required but was not found in PATH." >&2
    exit 1
  }
}

need lms
need jq

# Make sure the headless daemon is available.
lms daemon up >/dev/null

mapfile -t MODELS < <(
  lms ls --json | jq -r '
    if type == "array" then .[]
    elif has("models") then .models[]
    else empty end
    | .modelKey // .model_key // empty
  ' | awk 'NF' | sort -u
)

if ((${#MODELS[@]} == 0)); then
  echo "No downloaded models were found."
  echo "Download one first, for example: lms get <publisher/model>"
  exit 1
fi

echo
echo "Downloaded LM Studio models"
echo "---------------------------"
for i in "${!MODELS[@]}"; do
  printf '  %2d) %s\n' "$((i + 1))" "${MODELS[$i]}"
done
echo "   0) Cancel"
echo

while true; do
  read -r -p "Choose a model [0-${#MODELS[@]}]: " CHOICE
  [[ "$CHOICE" =~ ^[0-9]+$ ]] || { echo "Please enter a number."; continue; }
  (( CHOICE == 0 )) && exit 0
  (( CHOICE >= 1 && CHOICE <= ${#MODELS[@]} )) && break
  echo "Choice out of range."
done

MODEL="${MODELS[$((CHOICE - 1))]}"

echo
echo "Selected: $MODEL"
echo "Context : $CONTEXT_LENGTH"
echo "GPU     : $GPU"
echo

read -r -p "Unload the current model and load this one? [y/N]: " CONFIRM
[[ "$CONFIRM" =~ ^[Yy]$ ]] || { echo "Cancelled."; exit 0; }

echo "Unloading currently loaded models..."
lms unload --all || true

echo "Loading $MODEL..."
lms load "$MODEL" --context-length "$CONTEXT_LENGTH" --gpu "$GPU" --yes

# Start the HTTP server only if it is not already running.
if ! lms server status >/dev/null 2>&1; then
  echo "Starting LM Studio server on $BIND:$PORT..."
  lms server start --bind "$BIND" --port "$PORT"
fi

echo
echo "Current LM Studio state:"
lms ps

echo
echo "API model list:"
if command -v curl >/dev/null 2>&1; then
  curl -fsS "http://127.0.0.1:${PORT}/v1/models" | jq . || \
    echo "API check failed. If the server uses another port, set LMS_PORT accordingly."
else
  echo "curl is not installed; skipping API check."
fi
```
