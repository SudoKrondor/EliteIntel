LM Studio на сервере Ubuntu без GUI

Руководство подготовлено Wim

Elite Intel: это руководство настраивает отдельную машину в локальной сети, на которой LM Studio работает для Elite Intel. После этого укажите в поле Адрес на вкладке «Сервисы» http://SERVER_IP:1234/v1/chat/completions и загрузите поддерживаемую модель google/gemma-4-e4b. Сервер должен слушать не только localhost (--bind 0.0.0.0, см. часть 2, § 9), а брандмауэр должен пропускать игровой ПК.

Часть 1. Ubuntu Server как хост для локального ИИ / LM Studio

Руководство по чистой базовой установке
Рекомендуемая база: Ubuntu Server 24.04 LTS (amd64)
Дата документа: 12 сентября 2026

1. Назначение

Это руководство готовит чистую машину с Ubuntu Server для работы локального ИИ без графического интерфейса, например LM Studio / llmster. Оно намеренно заканчивается до установки самого LM Studio. Цель — небольшой и понятный сервер с работающими сетью, SSH, обновлениями, брандмауэром и, если нужно, проверенным драйвером NVIDIA.

Это не руководство по восстановлению или диагностике оборудования. Предполагается, что машина стабильно работает на штатных настройках CPU/RAM, а важные данные уже сохранены.

2. Какая версия Ubuntu?

Для консервативного, долгоживущего ИИ-сервера в этом руководстве используется Ubuntu Server 24.04 LTS (Noble Numbat). Canonical обеспечивает стандартное обслуживание безопасности Ubuntu 24.04 LTS до мая 2029 года. Ubuntu 26.04 LTS тоже доступна и является более новой LTS, но 24.04 по-прежнему полностью поддерживается и остаётся зрелой основой для систем, где стабильность важнее самого нового ядра и пользовательского окружения.

Для совершенно новой установки, когда новому оборудованию нужен самый свежий стек ядра и драйверов, Ubuntu 26.04 LTS — тоже разумный выбор. Команды в этом руководстве намеренно стандартные и должны остаться практически такими же.

Официальные ссылки:

  • https://ubuntu.com/about/release-cycle
  • https://documentation.ubuntu.com/release-notes/24.04/
  • https://ubuntu.com/server/docs/tutorial/basic-installation/

3. Перед установкой

Подготовьте:

  • 64-битную машину Intel/AMD (amd64).
  • USB-накопитель с ISO-образом Ubuntu Server.
  • По возможности проводной Ethernet.
  • Имя хоста, имя пользователя и надёжный пароль.
  • Решение, какой диск Ubuntu может стереть.
  • Для инференса на GPU — поддерживаемую видеокарту NVIDIA, правильно установленную и подключённую к питанию.

Если раньше CPU или RAM работали с разгоном, перед вводом машины в эксплуатацию как сервера верните стабильные штатные настройки. Среды выполнения ИИ и компиляция модулей ядра могут выявить нестабильность, которая не проявляется при более лёгкой нагрузке.

4. Установка Ubuntu Server

Загрузите установщик Ubuntu Server и следуйте обычному порядку. Для простого выделенного сервера:

  1. Выберите язык и раскладку клавиатуры.
  2. Позвольте установщику сначала настроить проводную сеть через DHCP.
  3. Используйте предназначенный системный диск. Разметка диска может уничтожить существующие данные, поэтому внимательно проверьте выбранный диск.
  4. Создайте пользователя-администратора и имя хоста.
  5. Выберите Install OpenSSH server, когда это будет предложено. Если не выбрали, его можно установить после первой загрузки.
  6. Пропустите дополнительные серверные snap-пакеты, если они вам специально не нужны.
  7. Завершите установку и перезагрузитесь.

5. Первый вход и обновление системы

Войдите локально или по SSH, затем обновите индекс пакетов и установленные пакеты:

sudo apt update
sudo apt upgrade -y

Если Ubuntu сообщает, что нужна перезагрузка:

sudo reboot

После повторного подключения проверьте версию системы и ядра:

lsb_release -a
uname -r

6. Небольшой набор инструментов администрирования

На ИИ-сервере без GUI полезны следующие пакеты:

sudo apt install -y \
  openssh-server \
  curl \
  ca-certificates \
  jq \
  htop \
  nvtop \
  ufw

curl используется установщиком LM Studio и для проверки API, jq делает вывод JSON читаемым, htop следит за CPU/RAM, nvtop — за GPU, а ufw даёт простой брандмауэр хоста.

Убедитесь, что SSH включён:

systemctl status ssh --no-pager

7. Доступ по SSH

Узнайте текущий адрес сервера:

ip -br address

С другой машины в локальной сети:

ssh YOUR_USER@SERVER_IP

Для регулярной работы аутентификация SSH по открытому ключу удобнее, чем каждый раз вводить пароль. На клиентской машине:

ssh-keygen -t ed25519
ssh-copy-id YOUR_USER@SERVER_IP

Проверьте новый сеанс SSH, прежде чем менять настройки парольной аутентификации. Не заблокируйте себе доступ к удалённому серверу.

Официальная справка по OpenSSH: https://ubuntu.com/server/docs/how-to/security/openssh-server/

8. Базовый брандмауэр

Перед включением UFW разрешите SSH:

sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status verbose

Для выделенного домашнего ИИ-сервера в локальной сети лучше открывать порты приложений только доверенным клиентам или доверенной локальной сети, а не всем сетевым интерфейсам без разбора.

Порт API LM Studio по умолчанию — 1234. Пока не открывайте его. Добавьте нужное правило, когда LM Studio будет установлен и станет ясно, каким клиентам нужен к нему доступ.

Официальная справка по брандмауэру: https://ubuntu.com/server/docs/how-to/security/firewalls/

9. Драйвер NVIDIA

Пропустите этот раздел, если сервер будет использовать инференс на CPU или ускоритель не от NVIDIA.

Сначала обновите систему и при необходимости перезагрузитесь. Затем позвольте Ubuntu определить подходящие вычислительные драйверы NVIDIA:

sudo ubuntu-drivers list --gpgpu

Для вычислительной/серверной нагрузки Ubuntu документирует автоматическую установку командой:

sudo ubuntu-drivers install --gpgpu

Перезагрузитесь после установки:

sudo reboot

Затем проверьте GPU:

nvidia-smi

Успешный вывод nvidia-smi показывает видеокарту, версию драйвера, температуру, VRAM и таблицу процессов.

Примечание о Secure Boot

Secure Boot требует совместимых подписанных модулей ядра. Инструмент ubuntu-drivers — предпочтительный способ установки, так как он предназначен для правильного выбора драйверов из пакетов Ubuntu. Если модуль NVIDIA не загружается, проверьте состояние Secure Boot, прежде чем раз за разом переустанавливать драйверы:

mokutil --sb-state

Не отключайте Secure Boot просто по привычке как первый шаг. Если у вашей комбинации прошивки и драйвера есть проблемы с подписью или регистрацией MOK, решайте их осознанно и документируйте изменение в BIOS.

Официальная справка по NVIDIA в Ubuntu: https://ubuntu.com/server/docs/how-to/graphics/install-nvidia-drivers/

10. Итоговая проверка готовности

Выполните:

hostnamectl
ip -br address
systemctl is-active ssh
sudo ufw status
free -h
df -h /
nvidia-smi    # NVIDIA systems only

На этом этапе на машине должны быть:

  • поддерживаемая установка Ubuntu LTS;
  • актуальные обновления пакетов;
  • рабочее подключение к локальной сети;
  • рабочий доступ по SSH;
  • базовый брандмауэр;
  • полезные инструменты администрирования;
  • проверенный драйвер NVIDIA, если применимо.

Сервер готов к установке LM Studio / llmster.

11. Что намеренно не рассматривается

Эта база не настраивает хранилище NAS/Samba, Docker, базы данных, веб-серверы, RAID, нестандартную разметку дисков, VPN, Pi-hole/DNS, графические окружения, CUDA Toolkit или ПО для конкретных приложений. Для этого нужны отдельные руководства.

Отдельный CUDA Toolkit не нужен только для запуска LM Studio на поддерживаемой видеокарте NVIDIA; используйте стек среды выполнения и драйверов, который поддерживает LM Studio, если только другому приложению специально не нужен набор разработчика CUDA.

12. Основы обслуживания

Периодически устанавливайте обычные обновления:

sudo apt update
sudo apt upgrade

Проверьте, не ожидается ли перезагрузка:

if [ -f /run/reboot-required ]; then
  cat /run/reboot-required
fi

Перед переходом на новый крупный выпуск Ubuntu прочитайте его примечания к выпуску и сделайте резервную копию сервера. Переход между выпусками — это не то же самое, что обычные обновления пакетов.

Часть 2. LM Studio как сервер без GUI и управление моделями

Установка, выбор модели, квантизация, служба API и переключение моделей
Цель: сервер Linux/Ubuntu без GUI
Дата документа: 12 сентября 2026

1. Назначение

Это руководство начинается с чистого сервера Ubuntu, на котором уже работают сеть, SSH и — для ускорения NVIDIA — проверенный драйвер GPU. Оно устанавливает среду LM Studio без GUI, объясняет, как выбирать и скачивать модели, при желании открывает локальный API и предлагает интерактивный Bash-скрипт для переключения моделей.

Серверный компонент LM Studio называется llmster. Программа командной строки для управления им — lms. Графический рабочий стол не нужен.

Официальная документация по работе без GUI: https://lmstudio.ai/docs/developer/core/headless

2. Три названия, которые стоит понимать

  • LM Studio — продукт и экосистема в целом.
  • llmster — серверный демон без GUI. Он выполняет службу инференса без графического интерфейса.
  • lms — CLI для скачивания, загрузки, выгрузки, просмотра и обслуживания моделей.

На выделенном Linux-сервере для инференса связка llmster + lms обычно самая чистая.

3. Установка llmster / lms

Устанавливайте от имени обычного пользователя, под которым будет работать служба, а не от root:

curl -fsSL https://lmstudio.ai/install.sh | bash

Запустите демон:

lms daemon up

Проверьте CLI:

lms --version
lms --help

Если оболочка не находит lms, откройте новую оболочку входа или добавьте каталог с исполняемыми файлами LM Studio в PATH текущей оболочки:

export PATH="$HOME/.lmstudio/bin:$PATH"

Чтобы закрепить это для Bash:

echo 'export PATH="$HOME/.lmstudio/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

4. Поиск и скачивание моделей

lms get без указания модели показывает рекомендации:

lms get

Скачайте модель по её имени в каталоге:

lms get publisher/model-name

Конкретная модель намеренно оставлена на выбор читателя, а не зашита в руководство.

Список скачанных моделей:

lms ls

Показать скачанные варианты/квантизации, если они есть:

lms ls --variants

Вывод в JSON удобен для скриптов:

lms ls --json | jq

LM Studio может скачивать поддерживаемые модели из своего каталога и экосистемы Hugging Face. Текущая версия CLI также позволяет указать квантизацию при скачивании, например:

lms get publisher/model-name@q4_k_m

Используйте названия квантизаций, которые действительно предлагаются для этой модели; не каждая модель публикуется во всех форматах.

Официальная документация по скачиванию моделей: https://lmstudio.ai/docs/cli/local-models/get

5. Размер модели и квантизация — объяснение для начинающих

Модель содержит миллиарды обученных числовых значений — весов. Более высокая точность чисел хранит эти значения точнее, но занимает больше места на диске и в RAM/VRAM. Квантизация сжимает модель, представляя эти значения меньшим числом бит.

Полезная аналогия — качественная аудиозапись: Q8 сохраняет больше деталей, Q6 сжимает чуть сильнее, Q4 — ещё сильнее. Это всё версии одной и той же обученной модели; Q8 не добавляет волшебным образом новое обучение или знания.

Типичная трактовка:

Квантизация Расход памяти Точность Практическая роль
Класс Q4 Ниже Хорошая Отличная отправная точка; часто достаточно для чата/работы с инструментами
Класс Q5/Q6 Средний Выше Хороший баланс качества и памяти
Класс Q8 Выше Очень высокая Используйте, когда дополнительная точность заметно помогает

LM Studio сам рекомендует выбирать 4-битный вариант или выше, если машина его тянет.

Важное правило

Не выбирайте Q8 только потому, что 8 больше 4. Выбирайте наименьшую квантизацию, которая надёжно справляется с вашей реальной задачей. Дополнительная точность ценна только тогда, когда она улучшает ответы, рассуждения, работу с инструментами или стабильность настолько, чтобы оправдать постоянно больший расход памяти.

6. Размер модели — не то же самое, что её интеллект

Квантизация и размер модели — разные решения.

Более крупная и способная модель с умеренной квантизацией может превзойти меньшую модель в Q8 на сложных рассуждениях. И наоборот, маленькая модель Q4 может идеально подходить для быстрой интерпретации команд.

При выборе модели учитывайте:

  1. Задачу: чат, программирование, вызов инструментов/функций, зрение, анализ данных, эмбеддинги и т. д.
  2. Архитектуру/число параметров: крупные модели часто способнее, но требуют больше памяти и могут работать медленнее.
  3. Квантизацию: Q4/Q6/Q8 меняет баланс точности и памяти для этой модели.
  4. Длину контекста: больший контекст может потреблять дополнительную память.
  5. Помещается ли в GPU: если модель и рабочий контекст целиком в VRAM, инференс на GPU обычно лучше всего.
  6. Поддержку инструментов: если приложению нужен нативный вызов функций/инструментов, выбирайте модель, обученную и поддерживаемую для этого.

Правильный выбор зависит от задачи. Проверяйте на реальных запросах, а не только по результатам бенчмарков.

7. Оценка памяти перед загрузкой

LM Studio может оценить расход ресурсов, не загружая модель:

lms load publisher/model-name \
  --context-length 8192 \
  --gpu max \
  --estimate-only

Это оценка, а не гарантия. Проверьте реально загруженную модель через lms ps, nvidia-smi и настоящий инференс.

8. Загрузка и выгрузка моделей

Загрузите скачанную модель:

lms load publisher/model-name --context-length 8192 --gpu max

--gpu max просит LM Studio перенести на GPU как можно больше. Без этого параметра LM Studio может выбрать автоматически.

Посмотреть, что загружено:

lms ps

Выгрузить модель интерактивно или по ключу:

lms unload publisher/model-name

Выгрузить всё:

lms unload --all

Официальная справка: https://lmstudio.ai/docs/cli/local-models/load

9. Запуск HTTP API

Для доступа только с самого сервера:

lms server start --bind 127.0.0.1 --port 1234

Проверьте:

curl -s http://127.0.0.1:1234/v1/models | jq

Чтобы слушать на всех интерфейсах IPv4:

lms server start --bind 0.0.0.0 --port 1234

Безопасность: привязка к 0.0.0.0 открывает службу для всех доступных сетей. Документация LM Studio рекомендует аутентификацию, если служба доступна не только с localhost. Как минимум ограничьте порт 1234 через UFW доверенными клиентами локальной сети или доверенной подсетью. Никогда не открывайте API инференса без аутентификации напрямую в интернет.

Пример для одного доверенного клиента:

sudo ufw allow from CLIENT_IP to any port 1234 proto tcp

Пример для доверенной частной подсети (замените на свою):

sudo ufw allow from 192.168.1.0/24 to any port 1234 proto tcp

Официальная справка по серверу: https://lmstudio.ai/docs/cli/serve/server-start

10. Проверка запроса инференса

OpenAI-совместимый API можно проверить через curl:

curl -s http://127.0.0.1:1234/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "publisher/model-name",
    "messages": [
      {"role": "user", "content": "Reply with exactly: Local inference works."}
    ],
    "temperature": 0
  }' | jq

Замените идентификатор модели на тот, что показывает lms ps или /v1/models.

11. Автозапуск LM Studio при загрузке

LM Studio документирует запуск llmster как задачи автозапуска systemd. Замените YOUR_USER, ключ модели, длину контекста и сетевую привязку на свои значения.

Создайте службу:

sudo nano /etc/systemd/system/lmstudio.service

Пример:

[Unit]
Description=LM Studio Headless Server
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
RemainAfterExit=yes
User=YOUR_USER
Environment="HOME=/home/YOUR_USER"

ExecStartPre=/home/YOUR_USER/.lmstudio/bin/lms daemon up
ExecStartPre=/home/YOUR_USER/.lmstudio/bin/lms load publisher/model-name --context-length 8192 --gpu max --yes
ExecStart=/home/YOUR_USER/.lmstudio/bin/lms server start --bind 127.0.0.1 --port 1234
ExecStop=/home/YOUR_USER/.lmstudio/bin/lms daemon down

[Install]
WantedBy=multi-user.target

Включите и запустите её:

sudo systemctl daemon-reload
sudo systemctl enable --now lmstudio.service
systemctl status lmstudio.service --no-pager

Затем проверьте:

lms ps
curl -s http://127.0.0.1:1234/v1/models | jq

Если быстрый запуск CLI выдаёт Text file busy

На некоторых системах второй вызов lms сразу после lms daemon up может конфликтовать с запуском демона. Только если вы действительно столкнулись с этой ошибкой, добавьте короткую паузу между двумя строками ExecStartPre:

ExecStartPre=/home/YOUR_USER/.lmstudio/bin/lms daemon up
ExecStartPre=/bin/sleep 5
ExecStartPre=/home/YOUR_USER/.lmstudio/bin/lms load ...

Не добавляйте обходные решения заранее, если простая служба работает.

Официальная справка по задаче автозапуска: https://lmstudio.ai/docs/developer/core/headless_llmster

12. Интерактивный переключатель моделей

Сопутствующий скрипт lmstudio-model-switcher.sh (полный текст в конце страницы) выводит простое нумерованное меню ключей скачанных моделей. Он:

  1. проверяет, что llmster запущен;
  2. читает скачанные модели из lms ls --json;
  3. спрашивает, какую модель использовать;
  4. выгружает текущие загруженные модели;
  5. загружает выбранную модель с настраиваемыми параметрами контекста/GPU;
  6. оставляет или при необходимости запускает службу API;
  7. показывает lms ps и проверяет /v1/models.

Установите его:

mkdir -p ~/bin
cp lmstudio-model-switcher.sh ~/bin/
chmod +x ~/bin/lmstudio-model-switcher.sh

Запустите с осторожными настройками по умолчанию (контекст 8192 токена, GPU max, API на localhost):

~/bin/lmstudio-model-switcher.sh

Переопределите настройки для одного запуска:

LMS_CONTEXT_LENGTH=16384 \
LMS_GPU=max \
LMS_BIND=0.0.0.0 \
LMS_PORT=1234 \
~/bin/lmstudio-model-switcher.sh

Важно: варианты / квантизации моделей

LM Studio различает логический ключ модели и её скачанные варианты квантизации. Скачивание publisher/model@q4_k_m выбирает, какую квантизацию хранить, а при загрузке обычно используется логический ключ модели, который показывает lms ls.

Если вы храните несколько квантизаций одной логической модели, посмотрите их так:

lms ls --variants
lms ls --json | jq

Поведение выбора вариантов менялось между версиями CLI LM Studio, поэтому перед автоматизацией переключения квантизаций сверьтесь с lms get --help / lms load --help установленной версии. Прилагаемый скрипт намеренно переключает ключи моделей — это стабильная и понятная операция для руководства общего назначения.

13. Смена модели по умолчанию при загрузке

Интерактивный переключатель меняет то, что загружено сейчас. Если служба systemd явно загружает модель при старте, после перезагрузки снова загрузится модель, прописанная в /etc/systemd/system/lmstudio.service.

Чтобы сделать другую модель постоянной моделью по умолчанию:

sudo nano /etc/systemd/system/lmstudio.service

Измените строку lms load ..., затем:

sudo systemctl daemon-reload
sudo systemctl restart lmstudio.service

В более продвинутой конфигурации можно использовать JIT-загрузку моделей вместо закрепления одной модели при старте. LM Studio поддерживает JIT-загрузку и автоматическую выгрузку; это полезно, когда приложения выбирают модели динамически.

15. Практический порядок выбора модели

Разумный способ выбрать модель:

  1. Сначала определите реальную задачу.
  2. Найдите модели с нужными возможностями (например, работа с инструментами, программирование, зрение или рассуждения).
  3. Сначала скачайте вариант класса Q4, если он есть.
  4. Если памяти впритык, перед загрузкой используйте --estimate-only.
  5. Проверьте реальные запросы и вызовы инструментов.
  6. Переходите на Q5/Q6, только если Q4 заметно теряет в надёжности или качестве.
  7. Переходите на Q8, только если улучшение заметно и стоит дополнительной RAM/VRAM.
  8. Если даже Q8 маленькой модели недостаточно, попробуйте более крупную/лучшую модель с умеренной квантизацией, а не рассчитывайте, что ещё большая точность решит проблему.

Так выбор модели остаётся эмпирическим, а не числовым: лучшая модель — это самая маленькая/быстрая конфигурация, которая надёжно отвечает потребностям приложения.

16. Контрольный список для устранения неполадок

Если LM Studio ведёт себя не так, как ожидалось, проверьте в таком порядке:

lms --version
lms daemon up
lms ls
lms ps
lms server status
nvidia-smi
free -h

Для модели, которая может не поместиться, сначала сделайте оценку:

lms load publisher/model-name --context-length 8192 --gpu max --estimate-only

Если удалённый клиент не может подключиться, сначала проверьте локально:

curl -s http://127.0.0.1:1234/v1/models | jq

Затем убедитесь, что сервер слушает на нужном адресе и порту:

ss -ltnp | grep 1234
sudo ufw status numbered

Если локальный доступ работает, а удалённый нет, проверьте адрес привязки, правила брандмауэра, маршрутизацию и аутентификацию API, прежде чем менять модель.

17. Что это руководство намеренно оставляет открытым

Оно не предписывает одну универсальную модель. Оборудование, задачи, длина контекста, архитектура модели и требуемые возможности слишком различаются. Оно также не требует отдельного CUDA Toolkit, Docker, графического рабочего стола или интеграций с конкретными приложениями.

Когда сервер стабилен, руководства для конкретных приложений могут определить свою модель, контекст, конечную точку API, аутентификацию и требования к производительности.

Приложение: lmstudio-model-switcher.sh

Сохраните это как lmstudio-model-switcher.sh, затем установите, как описано в части 2, § 12.

#!/usr/bin/env bash
set -euo pipefail

# LM Studio interactive model switcher
# Optional environment overrides:
#   LMS_CONTEXT_LENGTH=16384 LMS_GPU=max LMS_BIND=0.0.0.0 LMS_PORT=1234 ./lmstudio-model-switcher.sh

CONTEXT_LENGTH="${LMS_CONTEXT_LENGTH:-8192}"
GPU="${LMS_GPU:-max}"
BIND="${LMS_BIND:-127.0.0.1}"
PORT="${LMS_PORT:-1234}"

need() {
  command -v "$1" >/dev/null 2>&1 || {
    echo "Error: '$1' is required but was not found in PATH." >&2
    exit 1
  }
}

need lms
need jq

# Make sure the headless daemon is available.
lms daemon up >/dev/null

mapfile -t MODELS < <(
  lms ls --json | jq -r '
    if type == "array" then .[]
    elif has("models") then .models[]
    else empty end
    | .modelKey // .model_key // empty
  ' | awk 'NF' | sort -u
)

if ((${#MODELS[@]} == 0)); then
  echo "No downloaded models were found."
  echo "Download one first, for example: lms get <publisher/model>"
  exit 1
fi

echo
echo "Downloaded LM Studio models"
echo "---------------------------"
for i in "${!MODELS[@]}"; do
  printf '  %2d) %s\n' "$((i + 1))" "${MODELS[$i]}"
done
echo "   0) Cancel"
echo

while true; do
  read -r -p "Choose a model [0-${#MODELS[@]}]: " CHOICE
  [[ "$CHOICE" =~ ^[0-9]+$ ]] || { echo "Please enter a number."; continue; }
  (( CHOICE == 0 )) && exit 0
  (( CHOICE >= 1 && CHOICE <= ${#MODELS[@]} )) && break
  echo "Choice out of range."
done

MODEL="${MODELS[$((CHOICE - 1))]}"

echo
echo "Selected: $MODEL"
echo "Context : $CONTEXT_LENGTH"
echo "GPU     : $GPU"
echo

read -r -p "Unload the current model and load this one? [y/N]: " CONFIRM
[[ "$CONFIRM" =~ ^[Yy]$ ]] || { echo "Cancelled."; exit 0; }

echo "Unloading currently loaded models..."
lms unload --all || true

echo "Loading $MODEL..."
lms load "$MODEL" --context-length "$CONTEXT_LENGTH" --gpu "$GPU" --yes

# Start the HTTP server only if it is not already running.
if ! lms server status >/dev/null 2>&1; then
  echo "Starting LM Studio server on $BIND:$PORT..."
  lms server start --bind "$BIND" --port "$PORT"
fi

echo
echo "Current LM Studio state:"
lms ps

echo
echo "API model list:"
if command -v curl >/dev/null 2>&1; then
  curl -fsS "http://127.0.0.1:${PORT}/v1/models" | jq . || \
    echo "API check failed. If the server uses another port, set LMS_PORT accordingly."
else
  echo "curl is not installed; skipping API check."
fi
